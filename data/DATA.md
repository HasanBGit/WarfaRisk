# Data

This repository ships **no raw or cleaned patient-level data** — for every
source, including the demo cohorts released under a redistribution-permissive
license. What it does ship: the EDA/cleaning code, the KEEP/DROP dataset
selection rationale, and the exact train/test ID splits, so that a third
party who independently obtains the source data can reproduce this project's
`cleaned/*.csv` files and land on the same splits and (with the same seed)
the same reported numbers.

## Why no data is bundled

- **IWPC-6256 / IWPC-1780** (the primary genetic+clinical cohorts, sourced
  via PharmGKB / the `warfit-learn` package) have no clear redistribution
  license attached in this project's source materials. PharmGKB-origin data
  generally requires accepting PharmGKB's own data-use terms directly from
  them, not via a third-party mirror.
- **MIMIC-III/IV demo and eICU demo** (clinical-only, no genotype, n=17/23/160)
  are released by PhysioNet under the **ODC Open Database License (ODbL)**,
  which does permit redistribution of derivative databases — but ODbL is
  share-alike (a derivative database must itself carry an ODbL notice) and
  requires an explicit attribution notice. That's a real licensing
  commitment on top of this repo's own Apache-2.0 code license, for
  disproportionately small demo cohorts. Deliberately left as a closed
  door for now, not an oversight — a reasonable follow-up if richer
  clinical-only reproducibility is wanted later.
- **`saudi_pgx_ngs`** (MENA population genetic data from a collaborating
  institution) is out of scope entirely — not documented here, not part of
  this release.

## What ships instead

- `data/dataset_decisions.json` — the KEEP/DROP verdict and rationale for
  every candidate source dataset (no patient data, decisions only).
- `data/splits/*.json` — the fixed train/test ID assignments this project's
  results were computed on (`{dataset_name, id_col, seed, train_ids,
  test_ids}` — bare ID lists, no clinical/genetic values), generated by
  `warfarisk.phase0_scaffolding` with seed `20260725`. Two independent
  regenerations from this seed produced byte-identical splits.
- `data/eda_notebooks/*.ipynb` — the cleaning/EDA code for every candidate
  source, with cell outputs cleared before being added to this repo (they
  were computed against real patient data and are not shipped).
- `data/eda_notebooks/figures_*.png` — static, aggregate EDA plots
  (correlation heatmaps, dose-distribution boxplots) — visual summaries
  only, no row-level values.

## Reproducing `data/eda_notebooks/cleaned/*.csv`

1. **IWPC-6256 and IWPC-1780**: request access via
   [PharmGKB](https://www.pharmgkb.org/) / the International Warfarin
   Pharmacogenetics Consortium dataset, or install the `warfit-learn`
   PyPI package (`uv sync --extra phase1`), which bundles a copy of the
   6,256-patient cohort.
2. **MIMIC-III Clinical Database Demo / MIMIC-IV Demo / eICU-CRD Demo**:
   download directly from PhysioNet — no credentialing is required for the
   "demo" subsets specifically (unlike the full databases):
   - https://physionet.org/content/mimiciii-demo/
   - https://physionet.org/content/mimic-iv-demo/
   - https://physionet.org/content/eicu-crd-demo/
3. Place the downloaded files where `warfarisk.common.paths` expects raw
   input (see that module's docstring), then run the notebooks in
   `data/eda_notebooks/` in numeric order (`00_...` through `09_...`) to
   regenerate `data/eda_notebooks/cleaned/*.csv`.
4. With the same seed (`20260725`, already fixed in
   `warfarisk.common.splits.DEFAULT_SEED`), the shipped `data/splits/*.json`
   files will line up with the freshly rebuilt `cleaned/*.csv` — the phase
   scripts read cleaned data by patient/stay ID via
   `warfarisk.common.splits.apply_split()`, not by row position, so this
   holds even if the rebuilt CSVs are in a different row order.

## Data-handling rule (please keep this invariant)

**No file in this repository ever pairs an ordered patient/stay-ID list with
an ordered outcome or prediction column.** `data/splits/*.json` contains ID
lists with no outcome values; result exports under `results/` contain only
aggregate metrics (coverage rates, mean SHAP values, MAE/R²/PW20 by group),
never a per-row `id, y_true, y_pred` table. This is deliberate: combining an
ID-ordered split file with an ID-ordered prediction file would let anyone
reconstruct real patient ID → real therapeutic dose pairs for the whole test
set — i.e. republish a column of the (not-redistributable) source dataset
under a different filename. If a future phase's output would produce a
per-row prediction export, it should not be added to `results/` or any other
tracked path in this repo.
